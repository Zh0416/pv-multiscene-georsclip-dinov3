# E03 hard-negative text diagnostic

Run this after E05 when both semantic extraction paths still fail E01.
E03 changes only the raw semantic score: it removes the maximum hard-negative
cosine term, leaving the existing normalized mean of the four positive text
vectors. The original full score is positive cosine minus maximum negative
cosine. Geometry, checkpoint, prompts, RGB normalization, locked split, CAM
target and metrics are fixed. Each score path gets its own site-weighted
calibrator fitted only on the three outer training folds; a no-hard-negative
path never reuses the original full-path calibrator. Native512 is the
registered primary E03 comparison; the same single-variable comparison on
sliding224 is a conditional follow-up after E05. No decoder is trained.

The command requires the complete E05 diagnostic directory under
`/kaggle/working/pvstudy/diagnostics/e05-recovered-native-v1`, including
`raw/*.npz`. The downloaded E05 review ZIP does not contain those raw maps.
If the Kaggle session reset, first restore the original E05 reference JSONs
and rerun `diagnose-semantic --recompute-native` as described in [E05](E05.md).
Keep GPU enabled and OpenCLIP at the version recorded by the original cache.

In the Kaggle Notebook, update the code to the latest
`codex/e05-semantic-probe` branch and run:

```python
from pathlib import Path
import subprocess
import sys

repo = Path('/kaggle/working/pv-multiscene-georsclip-dinov3')
subprocess.run([
    sys.executable, '-m', 'pvstudy.cli', '--config', 'config.kaggle.b32.json',
    'diagnose-hard-negatives',
], cwd=repo, check=True)
```

The command checks the original QC lock, manifest and label/image hashes,
original C1 reports, E05 identity and every E05 raw-map SHA-256. Each freshly
computed full-text map must match the corresponding E05 map. After scoring,
all four full-text fold metrics must reproduce E05 and the original native
C1 metrics. The new positive-only maps, metrics, calibrators and predictions
are stored only in a new E03 diagnostic directory. Interruptions can be
resumed; completed positive-only maps are hash-checked and reused.

After `E03 complete`, download:

```text
/kaggle/working/pvstudy/diagnostics/e03-no-hard-negatives-v1/e03_review.zip
```

The ZIP includes `e03_summary.json`, four fold reports, identity and four
fixed-rule comparison previews. Full raw maps and predictions stay in the
Kaggle diagnostic directory. Summaries contain site-macro AP, Dice/IoU,
negative-site FP, area calibration, paired site bootstrap and fold deltas.

The preregistered reason to retain hard negatives is a reduction in negative
FP by at least 0.005 with positive-site AP loss no more than 0.01. The
summary reports this decision separately for native512 and sliding224. It
also reports whether each positive-only path passes E01 against the constant
baseline (AP gain >=0.05, at least 3/4 positive folds). E03 by itself does
not pass G2, promote a semantic path or unlock the test partition.
