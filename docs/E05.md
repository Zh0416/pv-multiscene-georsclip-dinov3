# E05 semantic localization diagnostic

Use after the original development CAM run shows poor C1 localization. The
command compares the current 512 patch projection with native-resolution
224 overlapping patch maps. It does not train a decoder or change the main
feature cache, CAM maps, split or previously reported results.

The first E05 implementation fixes all geometry before collecting results:
224 x 224 windows start at 0, 96, 192 and 288 on each axis, giving 16 windows.
Four windows are encoded per batch. Each uses the native 7 x 7 positional
grid. Scores use the existing positive prompt ensemble minus maximum hard
negative cosine, average overlapping raw margins on the aligned original
16 x 16 patch grid, then interpolate once to 32 x 32 with align_corners=False.
There is no crop resizing, per-image min-max normalization, CLS broadcasting
or text change. The original full-image global CLS score remains unchanged.

Run in the existing Kaggle session with GPU enabled and the original
`/kaggle/working/pvstudy` directory present. Required inputs are the locked
manifest/split, cache/index.json and all development feature files, source
images/masks, and the GeoRSCLIP checkpoint. DINOv3 is not loaded. The OpenCLIP
version must match the original cache (4.2.2 for the supplied run).

```python
from pathlib import Path
import subprocess
import sys

repo = Path('/kaggle/working/pv-multiscene-georsclip-dinov3')
subprocess.run([
    sys.executable, '-m', 'pvstudy.cli', '--config', 'config.kaggle.b32.json',
    'diagnose-semantic',
], cwd=repo, check=True)
```

The command reports `extracted` or `reuse` for every development image and
ends with `E05 complete`. Download:

```text
/kaggle/working/pvstudy/diagnostics/e05-native224-v1/e05_review.zip
```

The bundle contains e05_summary.json, four fold reports, timing.json,
identity.json and four labeled previews. Full raw maps and calibrated
predictions stay in the diagnostic directory. Previews show the smallest,
median and largest positive target fractions and the first negative ID
within development, using a fixed blue=0/red=1 probability scale. They are
diagnostic examples rather than evidence that the method improved.

On interruption, rerun the same command. Completed extraction maps are
hash-checked and reused. If code, data, runtime, GPU or cache identity changes,
the command refuses to mix outputs; preserve the old run and select a new
`--run-name`, for example `--run-name e05-native224-v2`. A new run name does
not change the experiment geometry. If the original Kaggle working directory
was reset, restore its full saved output or use the explicit semantic-only
recovery mode below. Do not rerun audit to recreate a different split.

For each outer fold, each path gets a separate site-weighted calibration
fit only on the other three folds. The summary pools validation site metrics
over all four folds. This frozen encoder / deterministic outer calibration
comparison has no network-training seed; it does not repeat the same C1
evaluation three times as independent evidence. Semantic seed/self/bank
retraining and downstream 4 x 3 runs are outside this diagnostic.

The native baseline uses original cached scores. Fresh native patch and
global scores must match those cached values within declared numerical
tolerances. If prior fold/seed-42 result-cam.json files are present, the
recomputed native C1 site metrics must match them too. Input file hashes,
QC lock, site separation, native prompt/preprocessing identity and the
GeoRSCLIP checkpoint are checked. Test image/label files are never opened.

Timing uses two warmup pairs, then three synchronized measurements of each
path per image, alternating order. Reported per-image time is the median
of those three trials; the overall ratio divides the mean sliding time by
mean native time. Individual ratio median/95th percentile/max are also
reported. Timing includes normalization, CPU-to-device transfer and score
stitching; it excludes disk reads, checkpoint loading and CPU metric work.
Allocated CUDA peaks are recorded for both paths. CPU fixture runs do not
qualify for the GPU runtime gate.

`E05_replacement.quality_pass` requires AP gain >=0.02, at least three
positive folds, negative FP increment <=0.005, and GPU latency ratio <=4.
The separate `E01_semantic` entries check AP gain >=0.05 relative to the
constant baseline and at least three positive folds. An E05 improvement
alone does not establish semantic quality or pass all of G2. The descriptive
paired site bootstrap uses 10,000 draws; development selection limits its
interpretation. No code automatically promotes the new path or unlocks test.

Local verification uses synthetic token maps to check overlap alignment and
unmodified global scores, a four-fold calibration isolation test, and a
TIFF/cache integration fixture with no accessible test files. That fixture
also verifies original result reproduction, extraction resume, untouched
input hashes and corruption rejection. Actual checkpoint localization and
CUDA timing must be established by the Kaggle run.

## When the original feature files are lost

The recovery bundle contains the unchanged locked manifest, split, original
cache index and four original seed-42 CAM JSON reports. It does not contain
images, feature arrays or trained model weights. Its file checksums are
listed in E05_RECOVERY_INFO.json. Attach `pvstudy-e05-recovery.zip` as a
private Kaggle dataset; either a mounted ZIP or automatically extracted
files are supported. This bundle is a local user artifact and is not
published with the repository code.

```bash
python -m pvstudy.cli --config config.kaggle.b32.json restore-e05 --source /kaggle/input
python -m pvstudy.cli --config config.kaggle.b32.json diagnose-semantic --recompute-native --run-name e05-recovered-native-v1
```

The restore step verifies all files and the QC/split reference, then copies
only the seven expected JSONs. It preserves existing files if they match
exactly and rejects conflicting files before writing anything. A different
bundle must be selected with an exact --source path when several are mounted.

With --recompute-native, native512 and sliding224 scores are both freshly
computed from the original GeoRSCLIP checkpoint, using the original prompts,
preprocessing and image hashes. DINOv3 and model training are not needed.
Both score maps are checkpointed under the new diagnostic directory for
resume; the main cache remains an index without its missing feature arrays.
The four original C1 reports are mandatory. All recomputed native per-site
AP/Dice/IoU/negative-FP values must reproduce those original reports within
1e-6, or the diagnostic stops. This checks the historical metric baseline;
it does not prove byte-identical recovery of the missing old arrays or the
old global scores. `original_native_arrays_verified` is explicitly false.
