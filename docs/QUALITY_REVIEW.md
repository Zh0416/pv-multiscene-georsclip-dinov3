# 人工质检：下一步操作

数据清单与编码器接口检查之后，先完成 G0 人工质检。质检页只展示影像和标签，
不展示模型预测，也不会自动确认或修改标签。

## 生成与打开

在已有清单和候选划分的 Kaggle 项目目录运行：

```bash
python -m pvstudy.cli --config config.kaggle.json export-qc
```

输出为 `/kaggle/working/pvstudy/qc/qc_review.html`，包含全部图像预览，可下载后
直接用 Chrome/Edge 打开，无需启动服务器或使用 GPU。原图、叠加图以 JPEG
预览，二值标签为无损 PNG；颜色直接采用原始第 1/2/3 波段，没有逐图拉伸。
它同时生成未确认的 `QC.template.json`，不会覆盖已有模板或替你勾选完成。

## 逐图检查

1. 检查影像颜色和波段顺序，标签是否覆盖光伏区域，边界是否存在明显错位。
2. 正图检查明显漏标、错标；负图检查是否遗漏光伏。小目标图优先显示。
3. 每张图选择“已检查，无待处理问题”或“发现问题，待处理”，写入必要备注。
   点击图片可打开 512 像素原尺寸预览。可以随时导出进度并用“恢复记录”导入。
4. 核实源场景关系与重复/近重复。页面列出跨开发/测试边界的 10 km 敏感性组，
   以及最近的跨分区图对；当前数据最近图对是 PV-64 / PV-66，约 5.008 km。
   几何距离不能证明源场景独立。缺乏来源依据时，在全局备注说明，并保留相应
   确认项未勾选。仅凭页面图片无法恢复缺失的日期、传感器或源场景元数据。
5. 根据实际完成情况勾选全局确认，点击“导出 QC.json”。仅有逐图记录尚不足以
   锁定，整体波段、对齐及源场景确认也必须成立。

全部图像必须已检查且无待处理问题。页面可以导出未完成的草稿，但 `lock-split`
会拒绝草稿、重复/缺失 ID、字符串形式的假布尔值以及对应旧清单/旧划分的记录。
导出记录内的身份哈希绑定影像/标签哈希、清单字段和精确分区，不随数据根目录改变。

如果确认存在跨分区同源场景，应先按 `DATA_PROTOCOL.md` 合组、重新生成候选并
重新核查。标签修订也须单独版本化。不能使用测试预测指导这些修改。

## 检查完成后

将实际导出的 `QC.json` 放入 Kaggle 项目工作目录，更新项目代码后依次运行：

```bash
python -m pvstudy.cli --config config.kaggle.json lock-split --qc-file QC.json
python -m pvstudy.cli --config config.kaggle.json cache
```

第一条必须成功后才执行第二条。锁定成功会保留 QC 文件哈希；缓存默认仅提取开发集，
当前划分应为 79 张。保留清单、锁定文件、QC 文件和缓存索引，防止会话重启后丢失。
后续才进行 CAM 单折训练与 G2/G3 评估。
