The [official GeoRSCLIP checkpoint listing](https://huggingface.co/Zilun/GeoRSCLIP/tree/main/ckpt)
contains `RS5M_ViT-L-14-336.pt` (1,711,947,530 bytes), with LFS SHA-256
`b0c2c660e917a7235f7aec346556d2696cbf419249cf75bcd8c17b822b76428c`.
The [OpenCLIP model configuration](https://github.com/mlfoundations/open_clip/blob/v2.24.0/src/open_clip/model_configs/ViT-L-14-336.json)
specifies a 336 input, 14-pixel patches, 24 visual blocks, width 1024 and
768-dimensional image/text embedding. The Kaggle copy is checked against that
SHA-256 before loading. Strict state-dict loading and a native 336 CLS identity
check still have to pass on Kaggle; the 1.7 GB checkpoint is unavailable locally.

For 512-pixel study images, the encoder replicates the right and bottom edge
to 518 pixels, so the 14-pixel convolution covers the entire source. Native
24x24 positional embeddings are bicubic-interpolated to a 37x37 patch grid;
raw patch scores are bilinear-resized to the fixed 32x32 CAM grid. The native
336 sliding path uses nine patch-aligned windows starting at 0, 98 and 182
pixels on each axis and averages overlapping raw scores before calibration.
E04 changes only the last of 24 visual blocks. E08 keeps 128/64 source crops
but resizes each to the new native 336 input before CLS scoring.

Use the existing, manually locked manifest and split. From a fresh Kaggle
notebook with Internet and GPU enabled:

```python
from pathlib import Path
import subprocess
import sys

repo = Path('/kaggle/working/pv-multiscene-georsclip-dinov3')
branch = 'codex/e05-semantic-probe'
url = 'https://github.com/Zh0416/pv-multiscene-georsclip-dinov3.git'
if (repo / '.git').is_dir():
    subprocess.run(['git', 'pull', '--ff-only', 'origin', branch], cwd=repo, check=True)
else:
    subprocess.run(['git', 'clone', '--branch', branch, url, str(repo)], check=True)
subprocess.run([sys.executable, '-m', 'pip', 'install', '-e', '.'], cwd=repo, check=True)

base = [sys.executable, '-m', 'pvstudy.cli', '--config', 'config.kaggle.json']
source = Path('/kaggle/working/pvstudy')
if not all((source / name).is_file() for name in ('dataset_manifest.json', 'split_lock.json')):
    source = Path('/kaggle/input/datasets/zh0416/pvstudy-e05-recovery')
subprocess.run(base + ['reuse-lock', '--source', str(source)], cwd=repo, check=True)
subprocess.run(base + ['prepare-source'], cwd=repo, check=True)
subprocess.run(base + ['verify-encoders', '--id', '正样本/PV-01.tif'], cwd=repo, check=True)
subprocess.run(base + ['diagnose-l14'], cwd=repo, check=True)
```

If the mounted recovery dataset contains only `pvstudy-e05-recovery.zip`, pass
that ZIP's exact path to `reuse-lock --source`. This copies only the locked
manifest and split, verifies the recovery checksums, and refuses to overwrite
a different lock. It does not restore any B/32 features.

The earlier `verify-encoders` failure came from the obsolete DINOv3 mount in
the first L/14 configuration. The new configuration uses the owner-confirmed
path above. The OpenCLIP message `No pretrained weights loaded` refers to
creation of the empty architecture; the configured `.pt` is loaded strictly
immediately after. `verify-georsclip` remains available for an isolated
GeoRSCLIP check when debugging a future DINOv3 mount issue, but it does not
complete the full G1 check.

The diagnostic uses only development images, writes resumable raw maps, and
fits a separate site-weighted calibrator for each score path on the three
training folds. It reports four-fold AP, negative-image false-positive area
and median encoder time per image. Download:

```text
/kaggle/working/pvstudy-l14-336/diagnostics/l14-semantic-v1/l14_review.zip
```

The older B/32 constant and E05 AP values are historical comparisons, not
L/14 control scores. The new summary recomputes the constant baseline on
the identical locked split. Changing encoder architecture is a protocol
amendment; any selected L/14 path requires a new development-gate and
downstream training run before claiming G2-G5 or opening test labels.
