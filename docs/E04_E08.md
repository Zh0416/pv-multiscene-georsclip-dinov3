# E04 final-block and E08 local-CLS diagnostics

These are isolated development-set diagnostics. They require the complete original
`/kaggle/working/pvstudy` output, including `dataset_manifest.json`, `split_lock.json`,
`cache/index.json`, four original fold-0..3/seed-42/result-cam.json reports, the full
E05 diagnostic directory and the full E03 diagnostic directory. The downloaded E03/E05
review ZIPs alone do not include their per-image `raw/*.npz` maps. If Kaggle reset,
restore or recompute those diagnostics before running either command. The commands
refuse changed manifests, splits, checkpoints, code identity, OpenCLIP version and
reference raw maps. They never read test images/labels or overwrite main caches.

E04 is the registered three-way comparison: native 512 versus value-only versus
genuine per-head V-V self-attention. Only the **last** visual transformer block is
changed. Both variants use patch tokens only inside that final block, preserving
its `ln_1`, `out_proj`, residual, `ln_2`/MLP, second residual, `ln_post` and visual
projection. Value-only directly projects each patch's V; V-V uses
`softmax(V V^T / sqrt(head_dim)) V` independently in each head. Both retain the
unchanged first eleven blocks, which already mix context. The original 512 CLS
global path is recomputed separately and checked against E05; neither candidate
replaces `s_global`. Primary comparisons use the original full text margin.
Positive-only comparisons are a labeled exploratory follow-up to E03, not an
additional preregistered E04 success route. Each score path gets its own calibrator
on the three training folds. Registered E04 replacement requires candidate minus
native AP >=0.01, negative-FP delta <=0.005, finite outputs and intact CLS.

E08 is a **new exploratory** local-CLS diagnostic. It fixes one geometry before
running: 128x128 source pixels, 64-pixel stride, 7x7 = 49 windows. Each RGB crop
is bilinearly resized to 224x224, CLIP-normalized, encoded by the original native
CLS path and scored against the E03 positive-text mean. Each window score covers
an 8x8 region of the 32x32 area grid; overlapping raw scores are uniformly
averaged before fold-specific calibration. The map has window-scale evidence,
not independent 32x32 localization. No alternative size, stride, text set or
stitch weighting is selected in this run.

Run from the existing Kaggle checkout after updating this branch:

```python
from pathlib import Path
import subprocess
import sys

repo = Path('/kaggle/working/pv-multiscene-georsclip-dinov3')
for command in ('diagnose-e04', 'diagnose-window-cls'):
    subprocess.run([sys.executable, '-m', 'pvstudy.cli', '--config',
                    'config.kaggle.b32.json', command], cwd=repo, check=True)
```

If the original E03 run used a different directory, pass `--e03-run-name NAME`.
Use a new `--run-name NAME` when changing code or environment; existing runs
cannot be silently mixed. The resulting download bundles are:

```text
/kaggle/working/pvstudy/diagnostics/e04-last-block-v1/e04_review.zip
/kaggle/working/pvstudy/diagnostics/e08-window-cls-v1/e08_review.zip
```

Each bundle includes a summary, four fold reports, identity and four fixed-rule
previews. Full raw maps and predictions remain in Kaggle diagnostic folders.
Check E01 versus constant (`AP >= constant + 0.05` and 3/4 positive folds),
negative FP at CAM threshold 0.25 and mean per-image inference time. A passing
single semantic CAM is not a G2/G3/G4/G5 pass or permission to use test labels.
Any selected new path requires locking the configuration and rerunning affected
paired main-pipeline controls on the same development folds before G6.
